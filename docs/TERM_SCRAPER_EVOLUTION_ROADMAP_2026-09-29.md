## 1. 主线判断

下一阶段应把内部事实单位从“一个表面词绑定四个译名”升级为“词在某处以某个词义出现，以及它在各版本中的实际表达”。分词器继续负责发现候选；结构对齐负责缩小搜索范围；宿主 agent 负责语义判断；程序负责核验证据、跟踪未完成项和发布兼容结果。

优先顺序是：**固定验收分母 → 建立出现位置与词义模型 → 五语对称发现 → 语境内多对多对应 → 自适应 agent 复核 → 全库覆盖核验 → 增量维护与历史数据重审**。每阶段都应交付可测的小步改进，避免再次把全部模块推倒后才评价效果。

本路线图不把“省译”“无法确定”“证据不足”改称成功。它们必须被准确登记，但仍然是严格全对应目标中的缺口。

## 3. 先明确“彻底”的计量方式

### 3.1 固定语料范围，不能用本地存在代替上线证明

以指定截止日期、五服发布依据和文本版本建立内容清单。分别记录“已上线但未抓到”“抓到但不完整”“无可靠上线依据”“内容版本不一致”。不能把采集失败改标成未上线，再从分母中删除。

先盘点项目已经支持及目标要求涵盖的文本域，逐域登记覆盖：不同剧情类型、区域对白、名称与说明等。当前 32 篇剧情只是开发实验集，不能代表所有文本域。对尚未接入的文本域明确列出缺口，不以缩小统计范围冒充全覆盖。

五种语言为 `ja`、`en`、`zh_hans`、繁中、`ko`；繁中的 `zh_tw`/`zh_hant` 兼容规则沿用现有入口，内部归一化不能造成两个服务器或两份文本被重复计数。

### 3.2 三种单位分别计数

1. **用语—词义—目标语言**：该词义在目标版本是否有经过核验的词或表达。某处被省译，但同词义在其它位置有明确对应，可以为词典层提供证据。
2. **具体出现—目标版本位置**：当前剧情当前话轮究竟如何表达。不得把其它故事里的对应词伪装成这一处出现的译文。
3. **实际公开查询**：旧入口在给定查询、语言及已有上下文参数下返回什么。内部收集齐了证据，却无法通过旧入口正确取得，仍是产品缺口。

“每个用语”需要一份版本化标注规则：专名、普通内容词、有意义的单字、复合词、固定表达、屈折变体、嵌套短语分别如何计数。不能继续以“不是专有名词”排除普通用语。功能词及语法化表达也必须在规则中明确范围和理由，不能临时作为停用词丢弃来提高分数。

### 3.3 至少保留以下仪表

| 指标 | 分母与判定 | 禁止的替代口径 |
| --- | --- | --- |
| 采集完整率 | 已核验五服共同上线清单中的应有文本单元 | 本地已存页面数 |
| 发现召回率、精确率 | 独立标注用语/出现位置；同时审查新候选是否成立 | 词表越长越好；未标注即错误 |
| 跨语严格正确覆盖率 | 金标要求中的正确词义、可接受跨度和真实出处全部满足 | 非空槽数量、模型接受率 |
| 已返回结果精确率 | 所有被系统发布为对应的结果中，独立核验正确的比例 | 减少返回即可宣称全覆盖 |
| 上下文语义表达覆盖率 | 明确单列词汇对应、改写、指代、非连续表达等类型 | 意译全部塞进“精确词名” |
| 审核覆盖率 | 应审对象中已经完成规定审核的比例 | 队列已导出或已排空 |
| 未决与错误存量 | 漏采、漏词、错界、错义、单次词、省译、歧义等分开统计 | 把暂缓删除、拒绝后不再计数 |
| 20 方向行为矩阵 | 每个来源语言到其它四语，分别报告正确、错误、缺失和样本量 | 只验日语/中文出发，再平均到五语 |

所有指标必须带语料版本、标签版本、代码版本和真实样本数。开发集、盲测集、难例集分别报告；宏平均、微平均与最差方向并列，不能让高频词或高资源语言掩盖低频缺口。

## 4. 分阶段路线图

下列验收门槛是建议的未来要求，不是已经取得的成绩。不在没有独立金标和吞吐数据时预报“下轮一定达到 99%”或给出虚假的完工日期。

| 阶段 | 主要交付 | 依赖 | 阶段出口 |
| --- | --- | --- | --- |
| P0：清单与独立评测 | 发布清单、标注规范、新盲测、错误分类、兼容快照 | 现在即可做 | 样本来源和分母可追溯，评测不读生产种子作为答案 |
| P1：出现位置与词义层 | 内部 occurrence/sense、原文跨度、证据关系、旧格式投影 | P0 的单位定义 | 已知多义/省译/改写难例可无损表示，旧接口契约通过 |
| P2：五语对称补漏 | 全文发现、分词多候选、遗漏台账、反向补漏 | P0；整合依赖 P1 | 冻结试验集全部窗口有处理记录，独立评测区分新增正确与新增噪声 |
| P3：语义对应 | 多对多跨度、同义归并、词义拆分、类型化证书 | P1；与 P2 迭代 | 二十个方向能区分正确对应、错误候选、缺失和歧义 |
| P4：自适应宿主 agent | 按需补证、反例检索、复核仲裁、改判与撤销 | P1/P3；恢复机制可提前做 | 受控对照显示新增正确收益，且所有新错有归因与发布阻断 |
| P5：覆盖核验闭环 | 全量未决账本、独立审核、冻结快照验收包 | P0–P4 | 不可漏账；全覆盖声明仅对逐项验收通过的明确范围成立 |
| P6：全库运行与维护 | 历史重审、增量失效、影子运行、发布回滚 | P5 的发布门槛 | 新旧数据同标准；中断可恢复；旧入口端到端兼容 |

P0 的评测设施和 P1 的最小内部模型应先完成。P2、P3 可在同一小批语料上交替演进；P4 逐步替换固定评审策略。P6 的容量和故障设计要提前验证，但批量发布应在质量门槛建立后进行。

### P0：先建立真正能否定改动的评测

交付内容：

- 完成当前 32 篇实验中剩余 26 个发现任务，保留原先 6 个任务的独立记录；处理新产生的翻译队列时仍单列未决。
- 为合并后的 187 个尚未找回标注词逐项分类：未进入候选、错误边界、被过滤、未被任务覆盖、agent 未发现、存储/查询丢失等。不能直接把某个模块当作所有遗漏的原因。
- 审核已提交的 267 个源表面词和 20 个翻译判断，分别建立词语有效性与跨语正确性标签。只审核接受项无法估计漏检。
- 新增按剧情/内容家族隔离的盲测。先做可完成的一批，再依据标注分歧、长尾分布和每方向样本量扩展；不把原有 345 个标签改名为盲测。
- 至少将提案和验收分开；严格语义验收由独立双语审校及分歧仲裁承担。不同提示词、同一模型重复判断，不算独立人工真值。
- 金标允许明确列出的合理词界和表达变体；审校分歧、无法确定项保留状态，不强行指定一个字符串作为唯一答案。按源词义和实际跨度评分，不能只比较词面是否相同。
- 同时建立官方结构化实体对照、普通词、单次词、同形异义、译文省略、跨话轮改写等测试分层。实体 ID 对照不能替代普通词语义标签。

验收：两次相同快照评测可重现；每个分数能追到原始条目；错误/缺失不被统计逻辑吞掉；金标不进入候选生成和任务包。盲测一旦用于调参，应转为开发集并补充新的留出样本。

### P1：在旧接口背后补齐数据表示

建议的内部链条：

`文本版本 → 结构位置 → 原文跨度 → 一次用语出现 → 词义 → 各语言实际表达 → 判断及证据`

这是数据关系设计，不要求引入图数据库。优先用现有存储体系和内部附加表实现，在隔离库验证迁移和兼容投影。

关键设计：

- 保存各版本自己的 scenario/talk 等可用结构标识；不同服务器的 ID 必须验证对应关系，不能因数字相同就合并。
- 标准化文本仅用于检索。正文原样保存，同时维护标准化位置到原文位置的映射，避免 NFKC、简繁归一、软换行或屈折归并损坏引用。
- `occurrence` 绑定语言、页面版本、话轮/结构单元、原文区间；`sense` 表示在语境中核实的词义。一个表面形允许多个词义，同一词义允许多个实际表达。
- 对应关系支持一对多、多对一、非连续跨度；省译、指代、改写、尚未判定保留独立类型。版本修订后生成新证据，不能覆盖旧出处后继续沿用旧结论。
- 将“来源权威”“同位结构”“语义审核”“发布状态”分开保存。出自官方正文不等于某条算法词对齐已经得到官方认证。
- 旧 term ID 保持可解析，用内部映射承接词义拆分。别名合并和词义拆分均要可撤销，不能因为归一化字符串相同自动混合证据。

首批建模验收使用已有难例：“声音”的音乐义与意见义；“演出阵容”的词汇对应与解释性改写；“朋友”的明确名词与语境替代。两故事出现相同字面，也必须先证实同义才能归入同一译名证书。

### P2：让五语都能主动发现，并持续检查漏掉了什么

发现层建议同时保留四类入口：官方实体与词表、语言适配分词/形态候选、统计与结构候选、宿主 agent 全文发现。各类输出进入同一原文跨度体系，保留候选来源供消融实验使用。

具体推进：

1. 五种语言分别扫描，不再只从已发现的日语或中文词向外扩展。目标语言发现新词时，也应回查其它四语。
2. 保留复合词与合理子词等重叠候选，由语境决定用途；避免在发现阶段过早做唯一切分。
3. 高频词用缓存和结构化证据减少重复工作；低频、单次、混合文字和文尾片段不能因预算耗尽静默丢弃。
4. 将每个正文窗口登记为未审、已审有新增、已审无新增、待扩上下文等状态，记录文本版本和处理者。
5. 对已有候选、被拒候选之外的正文做专门补漏；同时反查“目标语有表达而来源语没候选”的位置。
6. 保留每语言和每难例类别的公平配额，防止队列只追逐容易解决或高频的词。低预期收益只能降低优先级，不能移出验收分母。

Unicode UAX #29 明确说明中日文可靠词界需要词典或其它定制机制，因此通用字符边界可作为基础设施，不能充当终局词义切分器。[R1]

验收：窗口处理记录全覆盖是运行门槛；独立金标召回和新增候选精确率才是效果门槛。两轮没有新增只是发现趋于饱和的信号，不能证明没有漏词。发现策略必须在固定范围与相同审核预算下做对照。

### P3：把同位穿透升级为词义和跨度对应

保留当前结构对齐成果。在配对话轮内部生成跨度候选，再允许有依据地扩展到相邻话轮、指代位置或其它同义实例。每一次扩展都保留来源，不把“附近出现”升级成同义结论。

核心判断顺序：

1. 源词这次出现是什么意义？
2. 目标版本表达了这个意义吗？若表达，实际跨度是什么？
3. 它是明确词汇对应、短语/非连续表达、语境改写、指代，还是省译？
4. 多个故事中的证据是否支持同一个词义及适用范围？
5. 该结论适合进入通用词名，还是只能用于某个出现位置？

对齐模型、向量检索和宿主 agent 都可以生成候选，但不能独立作发布证书。awesome-align 的论文与实现采用配对语料、显式词位置和对齐错误率评估；其方法并不提供本项目五语、全部用语零错保证。是否引入应通过本项目盲测消融决定，不预先绑定某个模型。[R2][R3]

跨语一致性按经过核验的同一词义检查：A→B→A 和 A→B→C→A 可以发现矛盾；通过循环不能单独证明正确，尤其不能把同一段语料经多个处理通道算成多份独立支持。

单次词必须获得正式处理路径：保留现有通用派生词名的两故事保护，新增内部、限制适用范围的出现级证书；依据真实对应跨度、官方同实体索引或独立双语审核决定是否接受。出现级证书不得直接外推为全局词名。只有完成存储验证器、证书校验和负例测试后，才能考虑更广的准入；不能仅将常量 2 改成 1。

验收：难例集应能发现错义、错对象、错位置和错误全局泛化。接受项必须在原文可读回，在金标中满足相应关系类型；每个方向的假接受单独报告并阻断相关发布。

### P4：把 agent 评审变成有状态、可补证的流程

继续使用现有提取、review export、review submit 流程。细粒度任务状态和证据版本由内部队列及任务材料承载，不要求用户新增命令或模型配置，不改变既有 accept/replace/reject 含义。

建议内部状态机：

`待发现 → 待对应 → 待补证 → 待复核 → 已核验/候选被否定/未决`

另有 `证据过期 → 重开`、`新反例 → 复核 → 改判或撤销`。候选被否定不等于整个用语永远无效；未决不学习成负规则。

每类任务尽量只要求一件事：找漏词、定边界、判断词义、找对应跨度、检查竞争候选、核验省译、仲裁冲突。任务给出原文、译文、结构位置、候选及不确定点，返回简短理由和证据引用，不要求保存模型的内部推理过程。

从固定三段上下文改为按需检索：

- 首轮保持小包；从现有最多三个语境出发，选择不同故事、不同句法和可能不同词义的实例。
- 证据不足时自动派生补证任务，追加新场景、完整相邻话轮、未展示的候选或反例；上下文预算只能控制批次大小，不能伪装成证据已经耗尽。
- 对多义、单次、同位多实体、官方/派生冲突等高风险项安排复核。复核先独立判读原始材料，再查看前一结论，减少沿袭错误的机会。
- 多模型或多次判断的一致只用作辅助信号；正式语义金标仍需要独立审校。置信度必须与盲测错误关联检验，不能直接相信模型自评分。
- 给队列加入有上限的重试、退避、租约到期恢复、逐任务收据及失效任务替换。429 或会话中断后继续处理尚未提交的任务，不能从头重复投票或重复写入。
- 已保护的 agent 结论必须有带理由、证据和版本的显式改判/撤销路径。保护避免自动覆盖，不应让错误永久不可改。

现有文件队列足以承载这一架构。MCP 2025-06-18 Sampling 规范可作为“由程序向客户端申请模型能力”的历史设计参照，但本路线图不要求接入该协议，也不将该版本规范冒称最新规范。[R4]

验证采用同范围、同预算的分层对照：确定性基线 → 加全文发现 → 加自适应补证 → 加复核。保留固定随机抽样部分，以及用于挖掘长尾的主动选择部分，分别报告。至少统计新增正确用语、净减少的真实缺口、新增误配、每项新增正确结果所耗时间和可观测 token 数。宿主不提供 token 用量时标为未知，不能伪造成本。

### P5：建立不会漏账的全量核验

为每个应验收的“用语/词义/目标语”与“出现/目标版本”建立要求条目。每条都有可追溯状态；未发现用语由独立标注与残余审查补入，不能只对系统已经知道的词生成要求。

例如，某次出现的目标表达要求可分为：词汇对应已核验、其它表达关系已核验、已核验省译、尚未解决。分类必须互斥且覆盖该要求全集；错误候选和错配记录另存，不能因删除输出而丢失错误历史。对严格词汇对应目标，后面三类均不得计入词汇对应成功。

最终验收分三个层级声明：

- **流程覆盖完成**：所有应处理单元都已进入流程并有记录。
- **审核完成**：所有规定项目已完成独立审核，含明确的缺失、省译和歧义。
- **严格对应通过**：对冻结范围和标注规则，所有要求都返回正确对应；不存在错误、缺失和未决。若真实目标版本没有相应词汇，必须明示该项未满足严格要求，不能删掉后声称达成。

抽样零错只适用于该样本，不能直接宣称全库或未来版本永久零错。要向极致推进，就必须不断扩大独立核验范围，直到覆盖冻结清单的全部要求，并随更新重新核验受影响部分。

验收包包含：范围清单、原文摘要、词义与跨度标签、全部裁决和仲裁出处、20 方向查询结果、未决清单、历史纠错记录、程序版本及复跑方法。原文材料继续留在本地，不把大量游戏正文作为路线图或代码提交公开发布。

### P6：历史数据重审与长期维护

先建立影子索引，重新评价历史 accepted 项，不借用旧状态作为金标。分别处理带官方依据、人工裁决、agent 证据、纯算法来源的数据；来源类别影响审核方式，不自动决定语义正确。

增量依赖链至少覆盖：文本内容 → 结构对齐 → 出现位置 → 词义归并 → 对应判断 → 旧格式投影 → 查询缓存。正文等长替换、词典变化、别名规则或算法版本变化，也要使相应依赖失效。

重审过程中保留旧快照；只有验证通过的内部世代才进入公开读取。迁移应幂等、可恢复、有回滚演练，不要求用户手工搬数据或换用新入口。对有争议的既有人工决定先生成冲突记录，不能由新算法直接覆盖。

性能验收分别测冷启动全量、普通增量、文本修订和队列积压恢复：记录耗时、峰值内存、任务量、缓存命中、存储增长和未决年龄分布。使用索引、按证据版本缓存和有界批处理；不再以静默截断长文本或丢掉低频词维持速度。

针对本轮确实出现过的 429/中断，以及日志中的 Windows 文件占用，安排持久化状态、原子发布、重试耗尽和进程重启的故障注入验收。没有复现和测量前，不把所有 WinError 5 都归结为某一个原因。

## 5. 对外兼容的明确边界

冻结并逐阶段核验：公开函数签名、CLI 命令/帮助/默认值、HTTP/MCP 请求和响应结构、字段类型及含义、状态和空值语义、旧 ID、现有存储版本读取和迁移行为。新增内部词义层不应要求调用者理解新数据库结构。

`term_lookup` 本身返回列表，可以研究用现有记录结构和证据字段表达可区分的结果，但旧 ID 稳定性、分页/排序和客户端假设都要先验证。`term_penetrate` 返回单个对象或 `None`，并已有 `story_key`；优先利用这个既有上下文收窄词义。不能将其悄悄改为列表，也不能把多个冲突译名拼成一个字符串。

如果同一表面词有多个词义，而调用没有足够上下文，即使内部词义库完整，也不能从相同输入判断调用者心里指的是哪一种；同一故事内也可能出现多义。必须沿用已有未决/空结果语义，或者在已有列表查询能力中提供可区分证据，不能按频率猜一个后标为准确。

因此必须分开汇报：内部事实覆盖、已有接口可表达覆盖、实际查询正确覆盖。在“接口和使用方法完全不变”的约束下，信息不足的单结果查询仍可能无法满足“每次都给唯一答案”；这是应列出的产品边界，不是通过调参能消除的漏词。

## 6. 建议立即执行的五个工作包

以下为下一轮顺序，不是本次已经执行。

| 顺序 | 工作包 | 具体交付与结束条件 |
| --- | --- | --- |
| 1 | 完成现有实验并分类残差 | 32/32 发现任务有记录；187 个当前标注漏词有分类；新增词与翻译队列的完成/未决分开统计 |
| 2 | 建立独立盲测与正确性审查 | 提案和审校分离；审核 267 个源表面词及 20 项翻译判断；建立五语新样本和 20 方向评分，不再以接收率代替精确率 |
| 3 | 实现最小出现/词义内部模型 | 仅选“声音”“朋友”“演出阵容”、一个单次词和一个重复同名位置，跑通表示、证据、旧格式投影与回归 |
| 4 | 试验自适应补证和复核 | 与固定三语境策略在相同范围/预算下对照；验证新增正确率、假接受、未决减少及中断恢复 |
| 5 | 扩到五语对称发现并锁定发布门槛 | 所有五语都有独立发现入口；最差语言方向和长尾指标可见；质量不足时继续影子运行，不批量发布 |

首轮结束后才用实测吞吐估算全库工期：按各类剩余任务数量乘以实测处理与复核时间，再加采集、返工和运行开销。模型 token 成本、人工审校时间、程序运行时间分别估计，不以一个平均值掩盖多义/单次词的高成本。

阶段继续推进的条件是：同预算下增加经独立确认的正确覆盖，且没有未处理的新误配进入发布集合。若净收益停滞，应按残差类别改变策略；不能靠不断增大模型、上下文或候选数继续消耗预算。
