# 术语质量评估

`evaluate_term_quality.py` 用同一组输入比较实现，运行时只读取本地数据，不写生产词槽、正文或缓存。没有本地数据库时仍可执行合成回归：

```powershell
python -X utf8 scripts/evaluate_term_quality.py
python -X utf8 scripts/evaluate_term_quality.py --store store --output work/term-quality.json
python -X utf8 scripts/evaluate_term_quality.py --code-root <旧版本目录> --store store --output work/term-quality-before.json
```

旧版本目录需要保留完整 `sekaisync` 包。比较前确认报告中的正文、标注、官方词表三项 SHA-256 相同。旧实现不必包含新的共享对齐器；这种情况下结构覆盖指标标记为未测量。

## 分开解释每一项指标

合成回归针对已发现的错误边界，包括长词、功能字、拉丁子串、二十个有向语言对的同次出现定位以及候选歧义。这些用例经过刻意构造；多语言名称是已知输入，所以通过定位测试不等于发现了正确译名。

真实语料召回只统计本地五种语言都有可用正文的章节。`zh_hant` 与 `zh_tw` 按现有别名规则处理，辅助页不进入样本。五语正文齐全是本地数据条件，不独立证明各服务器的正式上线日期。

评估会屏蔽整份人工标注种子，保留 `official=1` 且非 demo 的官方词表作为生产输入。报告同时列出词表命中的标注子集与其它标注词，不能把官方词表命中说成无监督发现。仓库标注仍可能在历史开发中被见过，因此此评估不是全新的盲测。

`recall` 以去重的标注表面词为分母；`story_term_recall` 以章节和词语的组合为分母。评分仅去除成对外引号，原文与运行时词名规范化不被修改。标注不是穷尽词典，未标注的输出不能自动算对或算错，因此精确率留空。

结构指标枚举五种语言的二十个有向组合，统计原始行有没有可用的对应跨度。这是覆盖率，不是语义准确率；错误版本也可能具有相同的说话人结构。报告保留未完整映射的章节和语言组合，供进一步检查。

## 全覆盖与零错误的验收条件

回归通过、结构覆盖完整、没有自动接受歧义，这三者都不足以证明所有术语已正确翻译。严格验收还需要冻结语料版本、独立标注每个词义及其各语实际跨度，并对全部二十个方向分别统计正确、错误、缺失、无法对应。省译、代词替代和同形异义需要单独标注；不能把待确认或空结果计成成功。

当前脚本没有这种穷尽的多语语义金标准，故明确输出 `full_coverage_zero_error_acceptance.demonstrated=false`。这一字段防止把局部回归的高分误报为全项目验收通过。
